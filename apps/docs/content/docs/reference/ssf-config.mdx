# `ssf.config.ts` reference

## Helper

```ts
import { defineConfig } from "@ssf/cli";

export default defineConfig({
  // ...workspace config
});
```

`defineConfig` returns the config unchanged and gives editors the
config type. All sections below follow that shape exactly.

## Sections

- `workspace:` — `publisher` (required non-empty string),
  `defaultMode: 'offline' | 'online'` (required).
- `license:` — `env` (required non-empty string: the one env var for the
  whole publisher suite) and `configFile` (required non-empty string:
  publisher-relative path in the user config directory).
- `keys:` — `dir` (required), `licenseKid`, `artifactKid`, `rootKid`
  (each required non-empty; rotation means minting a new `kid`).
- `limits:` — `defaultMaxLines` (positive, at most 500),
  `defaultMaxChars` (positive), `defaultScriptOutputChars` (positive),
  `defaultScriptTimeoutSeconds` (positive).
- `agent:` — `confidentialityNotice: { enabled, text? }`,
  `allowedTools?` (opt-in only; never generated by default).
- `build:` — `obfuscate: { scripts, runtime }`, `diversify`
  (default on in the specified design).
- `skills:` — required array of skill directory paths.
- `plugins:` — required array (empty until the plugin API lands in a later
  release).

## Example

Example values: publisher `acme`, offline default, an `ACME_SSF_LICENSE`
env var plus an `acme/license` config file, full `limits`, notice enabled
with default text, `allowedTools: undefined`, obfuscation and
diversification on, two skills, no plugins.

## Safety rule

`ssf.config.ts` is executed code (like `vite.config.ts`). Never run `ssf`
in an untrusted workspace — the CLI prints this warning on `--help` and
`list`.

Identity, keys, logs, and plugins stay at workspace level; version,
content key, and manifest stay at skill level. The plugin pipeline is a
later release.
